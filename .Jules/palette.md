## 2026-04-09 - Modal Component ARIA Boundaries and useId Fallbacks
**Learning:** Custom modals must explicitly declare ARIA boundaries (`role="dialog"`, `aria-modal="true"`, and `aria-labelledby`) for screen reader access. Additionally, when mapping an `aria-labelledby` property to the modal's title `id`, Next.js/React 18's `useId()` hook should be used but requires a fallback string (`useId() || 'fallback-id'`) to prevent crashes or `undefined` values in static testing/verification environments where framework context may be missing. Always apply `aria-hidden="true"` on decorative icons and provide descriptive `aria-label` texts on icon-only buttons like "Close modal". Keyboard users also require distinct visual focus states on interactive elements (`focus-visible:ring-2 focus-visible:ring-primary-500`).
**Action:** Always implement comprehensive ARIA properties when building or modifying custom UI overlays/modals in this application. For dynamic IDs, use `useId()` combined with a default string fallback. Remember to implement visible keyboard focus states and decorative hiding attributes.
