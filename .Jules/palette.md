## 2024-05-11 - Modal Accessibility Pattern
**Learning:** Found that the standard Modal component in the design system lacked critical ARIA attributes (role='dialog', aria-modal, aria-labelledby) and keyboard focus indicators for the close button. Adding these is crucial for screen reader users and keyboard navigators.
**Action:** When implementing or reviewing future modal or overlay components, ensure they map title IDs correctly using `useId()`, define the dialog role, and explicitly hide decorative icons from screen readers while providing focus states for all interactive elements.
## 2026-10-19 - Sidebar Accessibility Navigation\n**Learning:** The navigation sidebar links lacked `aria-current="page"` for active state indication to screen readers, and decorative SVG icons were missing `aria-hidden="true"`. Furthermore, standard keyboard navigation via Tab requires explicit `focus-visible` utility classes (e.g., `focus-visible:ring-2`) to clearly show focus without impacting mouse users.\n**Action:** Always ensure active links use `aria-current="page"`, hide purely decorative icons with `aria-hidden="true"`, and use Tailwind's `focus-visible` classes to provide clear keyboard focus indicators across all interactive elements.
