## 2024-11-20 - Custom Modal Accessibility Implementation
**Learning:** Custom modals in this Next.js application lacked explicit ARIA boundaries, making them effectively invisible to screen readers as dialogue overlays. The nested structure required `role="dialog"`, `aria-modal="true"`, and `aria-labelledby` directly on the inner modal container (not the outer backdrop), along with an `id` on the title element to associate the accessible name properly. Icon-only buttons like the close action need an `aria-label` and `aria-hidden="true"` on the SVG itself, plus `focus-visible` styles (`focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-primary-500`) to enable keyboard navigation tracking.
**Action:** When building or modifying custom overlays or modal components in this design system, ensure these ARIA roles and properties (`role="dialog"`, `aria-modal`, `aria-labelledby`, and `focus-visible` states on icon buttons) are standard practice.
