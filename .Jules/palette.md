## 2024-05-11 - Modal Accessibility Pattern
**Learning:** Found that the standard Modal component in the design system lacked critical ARIA attributes (role='dialog', aria-modal, aria-labelledby) and keyboard focus indicators for the close button. Adding these is crucial for screen reader users and keyboard navigators.
**Action:** When implementing or reviewing future modal or overlay components, ensure they map title IDs correctly using `useId()`, define the dialog role, and explicitly hide decorative icons from screen readers while providing focus states for all interactive elements.
## 2024-10-07 - Empty State Actions and Table Integration
**Learning:** Found that pages displaying lists of items (Scorecards, Rocks, Meetings) used unhelpful plain text fallbacks (e.g., "No rocks") when empty, leaving users without a clear path to begin. Furthermore, integrating the existing `EmptyState` component into HTML tables requires carefully wrapping it in `<tr><td colSpan={X} className="p-4">...</td></tr>` to preserve valid table structure while ensuring sufficient padding.
**Action:** Always utilize the `EmptyState` component for empty collections to provide a clear description and immediate "call-to-action" button. Ensure correct table semantic wrapping when replacing text inside `<tbody>`.
