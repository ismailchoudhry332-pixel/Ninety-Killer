## 2024-05-11 - Modal Accessibility Pattern
**Learning:** Found that the standard Modal component in the design system lacked critical ARIA attributes (role='dialog', aria-modal, aria-labelledby) and keyboard focus indicators for the close button. Adding these is crucial for screen reader users and keyboard navigators.
**Action:** When implementing or reviewing future modal or overlay components, ensure they map title IDs correctly using `useId()`, define the dialog role, and explicitly hide decorative icons from screen readers while providing focus states for all interactive elements.
## 2026-09-24 - Sidebar Navigation Accessibility
**Learning:** The main application sidebar navigation lacked critical ARIA attributes and focus-visible indicators. For screen readers, it's essential to use `aria-current="page"` on the active link to provide context. Furthermore, purely decorative icons alongside text labels must include `aria-hidden="true"` to prevent redundant announcements. Keyboard navigators rely on clear focus rings, such as Tailwind's `focus-visible:ring-2 focus-visible:ring-primary-600 focus-visible:ring-offset-2`.
**Action:** When creating or reviewing navigation menus, always ensure the active state is communicated via `aria-current`, apply distinct `focus-visible` utility classes for keyboard users, and mark decorative SVGs as hidden from screen readers.
